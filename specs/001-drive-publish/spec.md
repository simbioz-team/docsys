# 001 — Выгрузка документов в Google Drive

- Заказчик: владелец (Рустам). Концепция согласована 10.11.2026.
- Основание: решение владельца 06.11.2026 (narta,
  `docs/sources/docs-service-concept-1106.md`): поток в одну сторону, git → Drive;
  правки методолога — отдельным файлом. 10.11.2026 владелец рассмотрел
  двустороннюю синхронизацию и вернулся к одностороннему потоку.

## Зачем

Сотрудники без доступа к репозиторию — методолог, менеджеры — не видят
документацию проекта и не могут её прочесть в привычном виде. Им нужен
актуальный документ по ссылке: прочесть, скачать в docx или pdf, оставить
комментарий.

## Принцип

**Источник правды один — git.** Drive — отображение: каждая выгрузка
перезаписывает документ целиком. Обратно ничего не идёт. Правки в Drive
затираются следующей выгрузкой. Замечания — комментариями или отдельным файлом,
их вносят в git люди.

## Решения владельца (10.11.2026)

| Вопрос | Решение |
|---|---|
| Сервис | Google Drive, формат Google Docs |
| Направление | только git → Drive |
| Когда выгружать | хуком агента при правке документа |
| Что выгружать | всё, кроме `archived` |
| Права сотрудников | комментатор |
| Где | общий диск организации (shared drive, Google Workspace); допустима папка в «Моём диске» личного аккаунта |

## Сценарии

1. **Первое подключение.** Администратор создаёт на общем диске папку, даёт
   группе сотрудников роль «Комментатор», себе — «Менеджер контента». В
   `.claude/doc-config.json` проекта вписывает `publish` с ID папки. Один раз
   входит в Google (`/doc-publish auth`), запускает `/doc-publish` — все
   документы появляются в Drive, структура папок повторяет репозиторий.
2. **Агент правит документ.** После правки хук пересобирает реестры и в фоне
   выгружает документ. Через несколько секунд сотрудник видит новую версию по
   той же ссылке.
3. **Документ сменил статус на `archived`, удалён или переехал.** Копия в
   Drive уходит в папку `Архив` внутри корневой. Ссылки сотрудников на неё не
   умирают.
4. **Человек поправил документ в редакторе, не через агента.** Хук этого не
   видит. Выгрузку делает `/doc-publish` — вручную или следующий агент.
5. **Выгрузка не удалась** (сети нет, токен отозван). Работа агента не
   блокируется. При следующей правке хук сообщает в контекст: «выгрузка в Drive
   не удалась: <причина>; повторить — /doc-publish».
6. **Сотрудник читает.** В начале документа — шапка: статус, тип, дата, путь в
   репозитории. Черновик помечен: опираться нельзя. Ссылки на другие
   выгруженные документы ведут в Drive.

## Требования

### Конфиг

- **R1.** Выгрузка включается разделом `publish` в `.claude/doc-config.json`.
  Нет раздела — выгрузки нет, хук и команда молчат (как весь плагин без
  конфига).

  ```json
  "publish": {
    "provider": "gdrive",
    "folder_id": "<ID корневой папки на общем диске>",
    "include": ["docs/**", "specs/*/spec.md"],
    "exclude": ["docs/journal/**"],
    "skip_statuses": ["archived"]
  }
  ```

- **R2.** Выгружаются только документы docsys (`docs_dir` и `extra_roots`, за
  вычетом `exclude` конфига) — и из них только отвечающие `publish.include` и не
  отвечающие `publish.exclude`. `include` по умолчанию — все документы.
  Шаблоны — как у `extra_roots`: от корня, `*` в пределах каталога, `**` —
  любая глубина.
- **R3.** `skip_statuses` по умолчанию — `["archived"]`. Документ со статусом
  из списка не выгружается, а его прежняя копия уходит в `Архив` (R9).

### Документ в Drive

- **R4.** Документ выгружается как Google Doc, сконвертированный из Markdown
  самим Drive. Frontmatter в текст не попадает.
- **R5.** Имя файла — `title` из frontmatter (нет — первый заголовок `# `, нет и
  его — имя файла без `.md`, как в реестрах). Для статусов кроме `active` к
  имени спереди добавляется метка: `[черновик]`, `[устарел]`, `[заменён]`.
- **R6.** В начале документа — шапка цитатой:

  > Статус: **draft** · Тип: adr · Обновлено: 2026-11-01 · Источник: `docs/decisions/adr-001-x.md`
  > ⚠ Черновик: опираться нельзя.
  > Документ выгружается из репозитория автоматически. Правки здесь будут затёрты — оставляйте комментарии.

  Отсутствующее поле — прочерк. Строка «⚠» — только у статусов кроме `active`,
  текст по статусу.
- **R7.** Ссылки в теле:
  - на другой выгружаемый документ — на его Google Doc
    (`https://docs.google.com/document/d/<id>/edit`), якорь отбрасывается;
  - на файл репозитория, который не выгружается (код, `plan.md`, документ вне
    `include`), — ссылка снимается, текст остаётся, после него в скобках путь
    от корня: `текст (в репозитории: specs/001-a/plan.md)`;
  - внешние (`http`, `https`, `mailto`) и якоря без пути — как есть.
  - Картинки с относительным путём заменяются текстом
    `[изображение: <путь от корня>]`. Выгрузка картинок — не в этой версии.
- **R8.** Папки Drive повторяют каталоги репозитория от корня:
  `docs/decisions/adr-001.md` → `<корень>/docs/decisions/<Документ>`. Папки
  создаются по мере надобности.

### Сопоставление и изменения

- **R9.** Связь «документ ↔ файл Drive» хранится в свойствах файла
  (`properties`, общих для всех приложений — не `appProperties`: те видны
  только записавшему их OAuth-клиенту, и выгрузка второго сотрудника не нашла
  бы файлов первого): `docsys_root` (ID корневой папки — проекты на одном диске
  не смешиваются), `docsys_id` (хеш пути от корня), `docsys_hash` (хеш
  выгруженного текста вместе с шапкой и именем). В `description` файла — путь в
  репозитории, для человека. Локального файла состояния нет: иначе две рабочие
  копии (worktree) разошлись бы.
- **R10.** Документ выгружается, только если `docsys_hash` отличается от хеша
  нового текста или файла в Drive ещё нет. Хеш считается после переписывания
  ссылок (R7): документ A, ссылавшийся на ещё не выгруженный B, перевыгружается,
  когда у B появляется ID.
- **R11.** Обновление сохраняет ID файла: ссылки сотрудников и комментарии на
  месте (комментарии к изменённому тексту могут оторваться — ограничение
  перезаписи целиком).
- **R12.** Копия, которой больше не соответствует выгружаемый документ (удалён,
  переехал, `archived`, выпал из `include`), переносится в папку `Архив` в
  корне. Не удаляется. Переехавший документ получает новую копию — по новому
  пути.

### Запуск

- **R13.** Хук `PostToolUse` (Edit|Write|NotebookEdit): правка документа,
  подлежащего выгрузке по R2, запускает выгрузку этого документа **в фоне** и не
  ждёт её. Хук не выгружает ничего, если нет `publish` или нет токена.
- **R14.** Хук сообщает в контекст о провале предыдущей выгрузки (сценарий 5) —
  одной строкой, один раз на провал.
- **R15.** Одновременно идёт не больше одной выгрузки на проект: блокировка в
  `.git/`. Вторая ждёт до 60 с, затем выходит с сообщением в журнал.
- **R16.** Команда `/doc-publish`:
  - без аргументов — полная выгрузка: все документы по R2, архивирование по R12;
  - `--dry-run` — что будет выгружено, обновлено, архивировано, без записи;
  - `auth` — вход в Google (R18);
  - `status` — сколько документов в Drive отстаёт от репозитория (отчёт).
- **R17.** Журнал выгрузок — `.git/docsys-publish.log`, последний итог —
  `.git/docsys-publish.status`. Не в рабочем дереве: не попадает в git.

### Доступ

- **R18.** Вход — OAuth 2.0 для настольных приложений с перенаправлением на
  `127.0.0.1`. Клиент (`client_id`, `client_secret`) — OAuth-клиент «Desktop
  app» проекта Google Cloud, тип согласия «Internal» (Workspace) или
  «External» в статусе «Testing» (личный gmail; Google отзывает токен через
  7 дней — выгрузка просит войти заново, `invalid_grant` не повторяется). Токен
  обновления хранится у пользователя: `~/.config/docsys/google.json`, права
  `0600`. В репозиторий не попадает. Область — `https://www.googleapis.com/auth/drive`
  (запись в папку, созданную не приложением, `drive.file` не даёт).
- **R19.** Права сотрудников docsys не раздаёт: они наследуются от общего диска
  или папки. Справочник описывает, как их выставить.

### Ограничения реализации

- **R20.** Зависимости — `bash`, `git`, `python3` (стандартная библиотека).
  HTTP — `urllib`.
- **R21.** Все запросы к Drive — с `supportsAllDrives=true`; поиск — с
  `includeItemsFromAllDrives=true` и `corpora=drive` + `driveId` общего диска
  (папка в «Моём диске» — `corpora=user`).
- **R22.** Адреса API и токена переопределяются переменными окружения — для
  тестов на поддельном сервере.

## Не входит

- Обратный поток: скачивание, сравнение, слияние, конфликты.
- Выгрузка картинок и вложений.
- Оглавление в Drive (`INDEX.md` как документ) — папок достаточно; вернуться,
  если сотрудники попросят.
- Выгрузка из CI и git-хуков.
- Раздача прав из docsys.
- Другие сервисы. Код делится на «что выгрузить» и «как выгрузить в Drive», чтобы
  второй поставщик добавлялся без переделки первого, но второго нет.

## Известные риски

- **Последний пишет — тот и прав.** Хук выгружает незакоммиченную правку. Две
  сессии (worktree) с разными версиями одного документа перезапишут друг друга;
  в Drive окажется версия последней правки. Принято владельцем: выбран хук, а не
  CI.
- **Конвертация Markdown → Google Docs не точная.** Сложные таблицы, HTML внутри
  Markdown, сноски могут выглядеть иначе. Проверяется на живом прогоне по
  корпусу narta.
- **Обновление содержимого Google Doc загрузкой Markdown** (`files.update` с
  медиа) должно конвертировать, как при создании. Проверяется живым прогоном
  первым делом; не работает — обновление через пересоздание с переносом ID
  невозможно, тогда — замена файла и перенос ссылок (решать с владельцем).

## Готовность

1. Проверки репозитория из `CLAUDE.md` зелёные.
2. Тесты на поддельном Drive (локальный HTTP-сервер) проходят:
   - первая выгрузка создаёт папки и документы, свойства R9 на месте;
   - повторная без правок — ни одного запроса на запись;
   - правка одного документа — одна запись; ID не меняется;
   - ссылки: на выгружаемый документ → Drive, на `plan.md` → текст с путём,
     внешняя — как есть;
   - шапка: статус, прочерк вместо отсутствующего поля, метка черновика;
   - `archived`, удаление, переезд, выпадение из `include` → `Архив`;
   - `include`/`exclude` отбирают по шаблонам;
   - хук: без `publish` — тихо; правка `plan.md` — нет выгрузки; провал —
     сообщение при следующей правке, одно;
   - `--dry-run` ничего не пишет.
3. Без раздела `publish` вывод всех проверок и реестры побайтово прежние
   (narta, study_mcp).
4. Живой прогон на общем диске владельца: выгрузка корпуса narta, обновление
   одного документа, архивирование. Нужны действия владельца — OAuth-клиент,
   папка, вход.
5. Версия поднята, `CHANGELOG.md`, `README.md`, справочник обновлены.
