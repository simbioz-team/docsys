Выгрузи документацию в Google Drive. Аргументы: `$ARGUMENTS` — пусто, `--dry-run`,
`status` или `auth`.

Поток в одну сторону: git → Drive. Документ в Drive — отображение, каждая
выгрузка перезаписывает его целиком. Правки в Drive затираются; замечания
сотрудники оставляют комментариями, их вносят в git люди.

## Шаг 1. Настроено ли

Прочитай `.claude/doc-config.json`. Нет раздела `publish` — скажи, что выгрузка
не настроена, покажи раздел «Настройка» ниже и остановись.

## Шаг 2. Прогон

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/publish.py" $ARGUMENTS
```

| Аргумент | Что делает |
|---|---|
| (пусто) | полная выгрузка: новые и изменённые документы, лишние копии — в `Архив` |
| `--dry-run` | что будет создано, обновлено, перемещено, архивировано — без записи |
| `status` | сколько копий в Drive актуальны, отстают, отсутствуют |
| `auth` | вход в Google — **запускает пользователь**, см. ниже |

Код 2 и «нет входа в Google» — вход не выполнен у этого пользователя. Не
пытайся войти сам: вход идёт через браузер. Предложи пользователю набрать:

```
! python3 "${CLAUDE_PLUGIN_ROOT}/scripts/publish.py" auth --client-id <ID> --client-secret <SECRET>
```

## Шаг 3. Итог

Перескажи итог одной строкой: сколько создано, обновлено, перемещено, ушло в
архив. Ошибка — приведи текст как есть и что делать.

## Когда выгрузка идёт сама

Хук после правки документа агентом выгружает этот документ в фоне. Полная
выгрузка нужна, когда:

- систему только подключили;
- документы правили руками, не через агента;
- документ удалили или переместили — старая копия уйдёт в `Архив` только при
  полной выгрузке;
- хук сообщил, что выгрузка не удалась.

## Настройка

1. **Папка.** Лучше — на общем диске организации: документы не привязаны к
   одному человеку. Сотрудникам (лучше группой) — роль «Комментатор», тому, кто
   выгружает, — «Менеджер контента». Подойдёт и папка в «Моём диске» личного
   аккаунта — тогда сотрудникам «Комментатор» на эту папку. Права раздаются в
   Drive, не docsys.
2. **OAuth-клиент.** В Google Cloud проекте: API Google Drive включён,
   учётные данные «OAuth client ID» типа «Desktop app».
   - **Google Workspace** — экран согласия «Internal». Токен бессрочный.
   - **Личный gmail** — «External», статус «Testing», себя и всех, кто будет
     выгружать, — в «Test users». Перевести в «In production» без проверенного
     домена нельзя, а в «Testing» Google отзывает токен через 7 дней: выгрузка
     скажет «войдите заново» — повторите `auth`. Чтобы снять ограничение,
     нужен домен (подойдёт сайт на GitHub Pages, подтверждённый в Search
     Console) и публикация приложения.
3. **Конфиг проекта**, `.claude/doc-config.json`:

   ```json
   "publish": {
     "provider": "gdrive",
     "folder_id": "<ID папки: часть адреса после /folders/>",
     "include": ["docs/**", "specs/*/spec.md"],
     "exclude": ["docs/journal/**"],
     "skip_statuses": ["archived"]
   }
   ```

   `include` не задан — все документы. `skip_statuses` не задан — `archived`.
4. **Вход** — `auth` (см. шаг 2). Токен — в `~/.config/docsys/google.json`, не в
   репозитории.
5. **Первая выгрузка** — `/doc-publish`.
